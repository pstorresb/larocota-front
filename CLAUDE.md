# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. `AGENTS.md` above is regenerated by `next dev` and only carries the Next.js 16 notice; keep the import so it stays visible.

## Commands

```bash
npm run dev          # next dev on http://localhost:3000
npm run build        # next build (also the only type check that runs today)
npm run start        # next start (production)
npm run lint         # eslint (flat config: next/core-web-vitals + next/typescript, no custom rules)
npx tsc --noEmit     # explicit type check; there is no "typecheck" script
```

There are **no tests** (no vitest/jest/playwright, no `test` script) and **no Prettier**. Setup: copy `.env.example` to `.env.local`. `NEXT_PUBLIC_API_URL` already includes the `/api/v1` prefix (`http://localhost:4000/api/v1`); `NEXT_PUBLIC_SITE_URL` feeds `metadataBase`.

The API is the sibling repo `../larocota-back` (separate git repository; read its `CLAUDE.md` for the domain model, money rules and error contract). Its `FRONTEND_ORIGIN` must equal this app's origin exactly because auth is a cross-origin httpOnly cookie sent with `credentials: "include"`.

## Architecture

Next.js 16 App Router, React 19, TypeScript strict, path alias `@/* -> src/*`. No route groups, no middleware/`proxy.ts`, no server actions. The home (`/`) is an async server component that reads `GET /catalog` and `GET /settings/public` per request through `src/lib/api/server.ts` (`cache: "no-store"`, base URL `API_INTERNAL_URL ?? NEXT_PUBLIC_API_URL`) and passes data as props to client islands, so the menu is in the first HTML. Every other page that shows data is still a `"use client"` component that loads with `useEffect` + `api.*`.

**Route protection is client-only.** `AdminShell` and `AccountPage` call `api.me()` and redirect; the admin HTML/JS is served to anyone. Real authorization lives in the API (`requireAdmin`/`requireSuperadmin`, ownership checks in SQL). Don't add UI that assumes hidden = protected.

`src/features/<domain>/` holds feature components and stores (`storefront`, `cart`, `checkout`, `auth`, `admin`). `src/components/site-header/` is the shared header (server component; `header-account.tsx` shows "Hola, {nombre}" or "Ingresar" from `api.me()`, `header-cart.tsx` opens the drawer on `/` and links to `/checkout` elsewhere via `features/cart/cart-ui-store.ts`). `src/components/ui/` has `Button` (variants `primary|secondary|ghost|on-brand|on-brand-ghost`, renders a `Link` when `href` is given), `Badge` (tones `brand|neutral|ok|warn|soldout`), `Skeleton`, `DatePicker`, `TimeSelect`, `DateTimeField`, `Segmented` and `ConfirmDialog`, plus the `.ui-field` / `.ui-control` field classes; there is still no generic `Dialog` or `Toast`.

## API client (`src/lib/api/client.ts`)

The single place that calls `fetch`. `request<T>()` adds `credentials: "include"`, sets JSON `Content-Type` unless the body is `FormData`, returns `undefined` on 204, and throws `ApiError { message, status, code }` using the API's Spanish `message` (fallback "No pudimos procesar la solicitud."). Current consumers only read `.message` and `.status === 401`; nothing branches on `code` yet.

All domain types (`AuthUser`, `CatalogProduct`, `ModifierGroup`, `AdminOrderDetail`, `AdminCycle`, …) are hand-written in this file; there is no shared contract with the API, so keep them in sync with the SQL selects and Zod schemas in `../larocota-back/src/modules/**`. Known holes: `createOrder(input: unknown)`, `uploadProof -> { proof: unknown }`, `setCycleProducts -> { products: unknown[] }`.

`src/lib/order-status.ts` holds the canonical status labels (`orderStatusLabel`) and shared `Intl` formatters (`money`, `longDate`, `longDateTime`, `shortDateTime`, `weekdayLongDate`, `weekdayDate`, `shortTime`, plus `slotRange`, `slotTimes`, `slotDayHeading`), all pinned to `America/Guayaquil` so server and client render the same text; prefer them over new inline formatters. `src/lib/cycle-status.ts` mirrors the API's cycle labels and admin transitions. Helpers: `productImageUrl(keyOrPath)` turns the API's `imageUrl` (`/media/products/<key>`, no `/api/v1` prefix) into an absolute URL and falls back to `/brand/hero-food.png`; `paymentProofUrl(proofId)` is fetched with `credentials` and shown via `URL.createObjectURL`; `googleAuthUrl(next)` sanitizes `next` against open redirects (the same check is repeated in `login/page.tsx` and `account/page.tsx`).

## Cart store (`src/features/cart/cart-store.ts`)

zustand + `persist` under `localStorage["larocota-cart-v3"]` with `skipHydration: true`: `<CartHydration/>` in the root layout calls `rehydrate()` once, and `useCartHydrated()` (a `useSyncExternalStore` over `persist.onFinishHydration`) gates every cart-dependent render, so server and first client render agree. Shape: `{ cycleId, items: CartItem[] }` (plus a non-persisted `cycleReset` flag) where each `CartItem` carries a client `id`, `productId`, `unitPrice` (already includes modifier deltas), `selections` (the exact payload the API expects) and `modifiers` (display-only labels). `MenuSection` calls `syncCycle(cycle.id)` after hydration: items from another cycle are dropped and `cycleReset` shows a notice. Identical products are not merged; `clear()` empties `items` but keeps `cycleId`.

Prices shown from the cart are a **preview**; `POST /orders/quote` is the source of truth and the checkout button stays disabled until a quote for the current cart signature succeeds.

## Styling

Hand-written CSS in `src/app/globals.css` (~1000 lines) with semantic class names (`.product-card`, `.checkout-shell`, `.admin-modal`). Tailwind v4 is imported for preflight only: **no utility classes are used anywhere**; keep writing semantic classes and tokens rather than mixing in utilities.

Tokens on `:root`: colors `--cream`, `--paper`, `--surface`, `--ink`, `--muted`, `--line`, `--brand` (#e92b25), `--brand-deep`, `--brand-soft` (tint), `--brand-ink` (cream text on red), `--ok`/`--ok-soft`, `--warn`/`--warn-soft`; radii `--r-sm|md|lg|xl|pill`; `--shadow-sm`, `--shadow`; type scale `--fs-xs … --fs-hero`; `--header-h`, `--gutter`. Font aliases `--font-display` (Poppins), `--font-body` (DM Sans) and `--font-script` (Allison) are declared on `body`, not `:root`, because `next/font` sets its variables on `<body>`. The red hero stays red in both themes. Dark mode is `html[data-theme="dark"]`, set by an inline `beforeInteractive` script in `layout.tsx` from `localStorage["larocota-theme"]` and toggled by `ThemeToggle`; redefine tokens under `:root[data-theme="dark"]`. The admin block uses the same tokens now (no literal brand hex) but still carries ~90 dark overrides. Labels are sentence case: no uppercase kickers.

Fonts are local (`src/app/fonts`, OFL licensed) via `next/font/local`: DM Sans variable (body, `--font-dm-sans`), Poppins 600/700 (display headings, `--font-poppins`), Allison (decorative script, `--font-allison`). Don't introduce Georgia or other faces.

Breakpoints in use: 950/1000 px (two-column layouts collapse) and 650/760 px (mobile: product modal becomes a bottom sheet with `dvh` + safe-area insets, sidebars hide). Icons are `lucide-react`. Images use `next/image`; remote product images go through `remotePatterns` in `next.config.ts` but most are rendered `unoptimized`.

For any new screen or redesign, use the `frontend-design` skill and extend the existing tokens and type scale instead of introducing a second palette.

## Business rules mirrored from the API

- Money: the catalog sends `basePriceCents` and `taxRateBps`; order/admin endpoints send decimal strings (`"12.50"`). Format with `Intl.NumberFormat("es-EC", { style: "currency", currency: "USD" })`. Never compute prices for anything the API can quote.
- All user-facing text is Spanish (Ecuador). Dates are formatted with `Intl.DateTimeFormat("es-EC", …)`; the API stores UTC.
- Phone numbers must match `^0\d{9}$`; inputs strip non-digits and cap at 10.
- Order statuses are the enum in `../larocota-back/src/modules/orders/state-machine.ts`; the canonical label map is `lib/order-status.ts`, but `admin/page.tsx` and `admin/orders/page.tsx` still keep local copies that must be updated together when a status is added.
- Fulfillment: `pickup` and `delivery` are enabled per cycle; the checkout only offers what the cycle allows and sends `address: null` for pickup. Every order also sends `slotStartsAt`, one of `cycle.slots[].startsAt` exactly as received; the API validates it and counts orders per slot. Orders carry `slotStartsAt`/`slotEndsAt` (null for orders placed before slots existed; fall back to `fulfillmentStartsAt`). Pickup address comes from `settings.pickup`.
- Stock: `CatalogProduct.available` drives "Agotado" badges, "quedan N" hints and disabled add buttons; `cycle.isOpen === false` disables adding and shows the opening date.
- Modifier rules (`selectionType`, `minSelections`/`maxSelections`, `includedQuantity`, `isLocked`) are validated in the product modal for UX only; the API re-validates in `resolveModifierSelection`.

## Known gaps and pitfalls

- No `robots.ts`, `sitemap.ts` or per-page `metadata`; `/admin` and `/account` are indexable. Root `error.tsx`, `loading.tsx` and `not-found.tsx` exist and cover `admin/[section]`'s `notFound()`.
- `account/page.tsx` only handles 401 and otherwise stays on "Cargando…".
- Modals/drawers have `role="dialog"` and labels but no focus trap or focus return; only the product modal closes on Escape and locks body scroll.
- Formatting: many files are written as very long single lines (up to ~3000 chars). That is debt from the absence of a formatter, not a convention; write new code in conventional multi-line style.
- `zod` is a dependency but unused in `src/`.
- Repeated helpers (currency formatter, status labels, phone regex, `useEffect` + `active` flag fetch pattern) exist in many files; prefer extracting before adding another copy.

See `../larocota-back/docs/roadmap.md` for the prioritized improvement plan; `docs/generated-assets.md` documents the AI-generated images in `public/`.
