# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. `AGENTS.md` above is regenerated by `next dev` and only carries the Next.js 16 notice; keep the import so it stays visible.

## Commands

```bash
npm run dev          # next dev on http://localhost:3000
npm run build        # next build (also the only type check that runs today)
npm run start        # next start (production)
npm run lint         # eslint (flat config: next/core-web-vitals + next/typescript, no custom rules)
npx tsc --noEmit     # explicit type check; there is no "typecheck" script
```

There are **no tests** (no vitest/jest/playwright, no `test` script) and **no Prettier**. Setup: copy `.env.example` to `.env.local`. `NEXT_PUBLIC_API_URL` already includes the `/api/v1` prefix (`http://localhost:4000/api/v1`); `NEXT_PUBLIC_SITE_URL` feeds `metadataBase`.

The API is the sibling repo `../larocota-back` (separate git repository; read its `CLAUDE.md` for the domain model, money rules and error contract). Its `FRONTEND_ORIGIN` must equal this app's origin exactly because auth is a cross-origin httpOnly cookie sent with `credentials: "include"`.

## Architecture

Next.js 16 App Router, React 19, TypeScript strict, path alias `@/* -> src/*`. No route groups, no middleware/`proxy.ts`, no server actions, no server-side data fetching: every page that shows data is a `"use client"` component that loads with `useEffect` + `api.*`. SSR therefore ships an empty shell and every page has a "Cargando…" phase.

| Route | Renders | Notes |
|---|---|---|
| `/` | `features/storefront/storefront.tsx` | Header, hero, category tabs, product grid, product modal (modifiers + lightbox), cart drawer, floating cart dock. One 20 KB file. |
| `/checkout` | `app/checkout/page.tsx` | Contact, pickup/delivery choice (from `cycle.fulfillmentModes`, pickup preferred), delivery address with geolocation/OpenStreetMap preview, bank card from `GET /settings/public` with copy button, proof upload. Calls `POST /orders/quote` on every cart change, then `POST /orders` + proof upload; if the upload fails after the order exists it redirects to the confirmation page with `?proof=missing`. Submit is blocked while `settings.payment` is `null`. |
| `/order-confirmation/[orderNumber]` | `app/order-confirmation/[orderNumber]/page.tsx` | Customer order detail: fetches `GET /orders/:orderNumber` (owner only), shows status, pickup point or address, payment deadline, steps, items, public history, and a proof upload zone while the order is `payment_pending` / `payment_rejected`. Account cards link here. |
| `/account` | `app/account/page.tsx` | Order list + profile form. Redirects admins to `/admin`, anonymous users to `/login?next=/account`. |
| `/login` | `app/login/page.tsx` (server) + `features/auth/login-form.tsx` | Login, signup with 6-digit email PIN, password reset with PIN, Google OAuth link. Reads `?next=` and `?google_error=`. |
| `/admin/*` | `app/admin/layout.tsx` wraps everything in `features/admin/admin-shell.tsx` | Client-side gate: `api.me()` then role check, else `router.replace`. `orders`, `users`, `page` (dashboard) are page-level clients; `products`, `categories`, `cycles` are 2-line wrappers around `features/admin/catalog-crud.tsx` with a `mode` prop (the cycle form exposes pickup/delivery checkboxes); `settings` edits the payment account and pickup point via `GET /admin/settings` + `PUT /admin/settings/:key` (superadmin writes, admin read-only); `[section]` is a stub that only knows `payments`. |

**Route protection is client-only.** `AdminShell` and `AccountPage` call `api.me()` and redirect; the admin HTML/JS is served to anyone. Real authorization lives in the API (`requireAdmin`/`requireSuperadmin`, ownership checks in SQL). Don't add UI that assumes hidden = protected.

`src/features/<domain>/` holds feature components and stores (`storefront`, `cart`, `auth`, `admin`); `src/components/` has only the shared `SiteHeader` and `ThemeToggle`. There is no `ui/` primitives folder: no `Button`, `Field`, `Dialog`, `Toast`, `Badge` or `Skeleton` components exist yet, so modals and buttons are re-implemented per page.

## API client (`src/lib/api/client.ts`)

The single place that calls `fetch`. `request<T>()` adds `credentials: "include"`, sets JSON `Content-Type` unless the body is `FormData`, returns `undefined` on 204, and throws `ApiError { message, status, code }` using the API's Spanish `message` (fallback "No pudimos procesar la solicitud."). Current consumers only read `.message` and `.status === 401`; nothing branches on `code` yet.

All domain types (`AuthUser`, `CatalogProduct`, `ModifierGroup`, `AdminOrderDetail`, `AdminCycle`, …) are hand-written in this file; there is no shared contract with the API, so keep them in sync with the SQL selects and Zod schemas in `../larocota-back/src/modules/**`. Known holes: `createOrder(input: unknown)`, `uploadProof -> { proof: unknown }`, `setCycleProducts -> { products: unknown[] }`.

`src/lib/order-status.ts` holds the canonical status labels (`orderStatusLabel`) and shared `Intl` formatters (`money`, `longDate`, `longDateTime`, `shortDateTime`, all in `America/Guayaquil`); prefer them over new inline formatters. Helpers: `productImageUrl(keyOrPath)` turns the API's `imageUrl` (`/media/products/<key>`, no `/api/v1` prefix) into an absolute URL and falls back to `/brand/hero-food.png`; `paymentProofUrl(proofId)` is fetched with `credentials` and shown via `URL.createObjectURL`; `googleAuthUrl(next)` sanitizes `next` against open redirects (the same check is repeated in `login/page.tsx` and `account/page.tsx`).

## Cart store (`src/features/cart/cart-store.ts`)

zustand + `persist` under `localStorage["larocota-cart-v3"]`. Shape: `{ cycleId, items: CartItem[] }` where each `CartItem` carries a client `id` (`crypto.randomUUID()`), `productId`, `unitPrice` (already includes modifier deltas), `selections` (the exact payload the API expects) and `modifiers` (display-only labels). `cycleId` is set by the storefront from `GET /catalog` and sent with every quote/order. Identical products are not merged; `clear()` empties `items` but keeps `cycleId`; there is no `skipHydration`, so the cart badge can differ between server and first client render.

Prices shown from the cart are a **preview**; `POST /orders/quote` is the source of truth and the checkout button stays disabled until a quote for the current cart signature succeeds.

## Styling

Hand-written CSS in `src/app/globals.css` (~650 lines) with semantic class names (`.product-card`, `.checkout-shell`, `.admin-modal`). Tailwind v4 is imported for preflight only: **no utility classes are used anywhere**; keep writing semantic classes and tokens rather than mixing in utilities.

Tokens on `:root`: `--paper`, `--surface`, `--ink`, `--muted`, `--line`, `--brand` (#e92b25), `--brand-deep`, `--shadow`. Dark mode is `html[data-theme="dark"]`, set by an inline `beforeInteractive` script in `layout.tsx` from `localStorage["larocota-theme"]` and toggled by `ThemeToggle`. Redefine tokens under `:root[data-theme="dark"]`; the admin section still uses literal hex values and needs ~90 dark overrides, which is known debt, not a pattern to extend.

Fonts are local (`src/app/fonts`, OFL licensed) via `next/font/local`: DM Sans variable (body, `--font-dm-sans`), Poppins 600/700 (display headings, `--font-poppins`), Allison (decorative script, `--font-allison`). Don't introduce Georgia or other faces.

Breakpoints in use: 950/1000 px (two-column layouts collapse) and 650/760 px (mobile: product modal becomes a bottom sheet with `dvh` + safe-area insets, sidebars hide). Icons are `lucide-react`. Images use `next/image`; remote product images go through `remotePatterns` in `next.config.ts` but most are rendered `unoptimized`.

For any new screen or redesign, use the `frontend-design` skill and extend the existing tokens and type scale instead of introducing a second palette.

## Business rules mirrored from the API

- Money: the catalog sends `basePriceCents` and `taxRateBps`; order/admin endpoints send decimal strings (`"12.50"`). Format with `Intl.NumberFormat("es-EC", { style: "currency", currency: "USD" })`. Never compute prices for anything the API can quote.
- All user-facing text is Spanish (Ecuador). Dates are formatted with `Intl.DateTimeFormat("es-EC", …)`; the API stores UTC.
- Phone numbers must match `^0\d{9}$`; inputs strip non-digits and cap at 10.
- Order statuses are the enum in `../larocota-back/src/modules/orders/state-machine.ts`; label maps live in `account/page.tsx`, `admin/page.tsx` and `admin/orders/page.tsx` and must be updated together when a status is added.
- Fulfillment: `pickup` and `delivery` are enabled per cycle; the checkout only offers what the cycle allows and sends `address: null` for pickup. Pickup address/hours come from `settings.pickup`.
- Stock: `CatalogProduct.available` drives "Agotado" badges, "quedan N" hints and disabled add buttons; `cycle.isOpen === false` disables adding and shows the opening date.
- Modifier rules (`selectionType`, `minSelections`/`maxSelections`, `includedQuantity`, `isLocked`) are validated in the product modal for UX only; the API re-validates in `resolveModifierSelection`.

## Known gaps and pitfalls

- No `error.tsx`, `not-found.tsx`, `loading.tsx`, `robots.ts`, `sitemap.ts` or per-page `metadata`; `/admin` and `/account` are indexable. `admin/[section]` calls `notFound()` with no boundary.
- `account/page.tsx` only handles 401 and otherwise stays on "Cargando…".
- Modals/drawers have `role="dialog"` and labels but no focus trap or focus return; only the product modal closes on Escape and locks body scroll.
- Formatting: many files are written as very long single lines (up to ~3000 chars). That is debt from the absence of a formatter, not a convention; write new code in conventional multi-line style.
- `zod` is a dependency but unused in `src/`.
- Repeated helpers (currency formatter, status labels, phone regex, `useEffect` + `active` flag fetch pattern) exist in many files; prefer extracting before adding another copy.
